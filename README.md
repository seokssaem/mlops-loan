# Loan Lab — 대출 승인 예측 MLOps 수업 예제

머신러닝 모델을 FastAPI로 제공하고, 사용자가 직접 입력해 결과를 확인하는 프론트엔드를 연결한 교육용 프로젝트입니다.

이 예제의 핵심은 화면을 예쁘게 꾸미는 것만이 아닙니다. **실제 서비스 조사 → 디자인 원칙 추출 → `DESIGN.md` 작성 → API 계약을 UI로 번역 → 구현과 검수**의 전체 흐름을 보여줍니다.

> 이 프로젝트는 UI/API/MLOps 학습을 위한 예제입니다. 모델 결과는 설명용 가상 예측이며 실제 신용평가, 대출 심사, 금융 상담에 사용할 수 없습니다.

## 학생이 배우는 것

- API 스키마를 읽고 필요한 UI 입력 요소를 설계합니다.
- 레퍼런스의 분위기가 아니라 반복되는 디자인 원칙을 찾습니다.
- 구현 전에 디자인 판단을 [`DESIGN.md`](DESIGN.md)로 문서화합니다.
- 로딩, 입력 오류, 서버 오류, 승인·미승인 상태를 함께 설계합니다.
- 모바일과 데스크톱에서 같은 기능을 검수합니다.
- 모델 출력의 불확실성과 한계를 사용자에게 정직하게 설명합니다.

## 작업 흐름

```text
레퍼런스 조사
    ↓
디자인 원칙 추출
    ↓
DESIGN.md 작성
    ↓
API 스키마를 UI 폼으로 변환
    ↓
프론트엔드 구현 및 /predict 연결
    ↓
반응형·상태별 검수
```

Threads에서 소개된 [Inspo](https://inspomcp.dev/) 방식처럼 코드부터 작성하지 않고, 먼저 실제 서비스의 화면을 관찰했습니다. Toss, 카카오뱅크, 케이뱅크, Upstart, Nubank에서 여백·정보 요약·신뢰 문구·단계화·투명성이라는 원칙을 추출해 이 교육용 서비스에 맞게 다시 설계했습니다.

## 실행하기

Python 3.10 이상이 필요합니다.

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

브라우저에서 다음 주소를 엽니다.

- 프론트엔드: `http://localhost:8000/`
- 수업용 데모 별칭: `http://localhost:8000/demo`
- Swagger API 문서: `http://localhost:8000/docs`
- 모델 상태: `http://localhost:8000/health`

Docker로 실행하려면 다음 명령을 사용합니다.

```bash
docker build -t loan-lab .
docker run --rm -p 8000:8000 loan-lab
```

## 프로젝트 구조

```text
mlops-loan/
├─ app/
│  ├─ main.py            # FastAPI 라우트와 정적 프론트엔드 제공

│  └─ static/
│     ├─ index.html      # 교육용 단일 페이지 UI
│     ├─ styles.css      # 디자인 토큰과 반응형 스타일
│     └─ app.js          # 단계 폼, API 호출, 결과 상태
├─ models/               # 학습된 모델과 인코더
├─ tests/                # 모델·API·프론트엔드 통합 테스트
├─ DESIGN.md             # 디자인 조사와 판단 근거
└─ Dockerfile
```

## API와 UI의 계약

프론트엔드의 한국어 라벨은 사용자를 위한 표현이고, `age`, `annual_income` 같은 영문 키는 서버와 약속한 데이터 계약입니다. 화면 문구는 바꿀 수 있지만 API 키와 자료형을 임의로 바꾸면 요청이 실패합니다.

### 요청 예제

```json
{
  "age": 35,
  "gender": "남",
  "annual_income": 5000,
  "employment_years": 5,
  "housing_type": "자가",
  "credit_score": 720,
  "existing_loan_count": 2,
  "annual_card_usage": 2400,
  "debt_ratio": 35.5,
  "loan_amount": 3000,
  "loan_purpose": "주택구입",
  "repayment_method": "원리금균등",
  "loan_period": 36
}
```

### 응답 예제

```json
{
  "request_id": "3f4db738-8dcf-4a89-b477-9e7fca830af2",
  "timestamp": "2026-09-23T01:23:45.000000+00:00",
  "approved": true,
  "probability": 0.8,
  "risk_grade": "A"
}
```

브라우저는 폼 입력을 위 JSON 구조로 바꿔 `POST /predict`에 보냅니다. 화면의 `API 응답 보기`를 누르면 서버가 돌려준 실제 JSON을 확인할 수 있습니다.

## 수업 진행 제안

### 1. 레퍼런스 조사

학생에게 다음 질문을 던져보세요.

- 금융 서비스는 어떻게 신뢰감을 주는가?
- 중요한 행동 버튼은 어디에, 어떤 색으로 배치되는가?
- 긴 폼을 어떤 그룹으로 나누는가?
- 결과의 불확실성을 어떻게 표현하는가?

### 2. DESIGN.md 검토

- 색상과 글꼴을 고른 근거는 무엇인가?
- 카드, 입력창, 버튼의 크기와 간격은 일관적인가?
- 승인·미승인을 색상만으로 구분하지 않았는가?
- 모바일에서 정보 우선순위는 어떻게 바뀌는가?

### 3. API 계약을 UI로 번역

- 13개 필드가 API의 키·자료형과 정확히 일치하는가?
- 범주형 항목을 자유 입력으로 받지 않았는가?
- `probability`의 0–1 값을 화면에서 퍼센트로 변환했는가?
- 로딩 중 버튼의 중복 클릭을 막았는가?

### 4. 검수

- 최소·최대 경계값이 올바르게 처리되는가?
- 422, 500, 503 응답이 이해하기 쉬운 문구로 표시되는가?
- 키보드만으로 모든 필드를 사용할 수 있는가?
- 작은 화면에서 결과와 버튼이 잘리지 않는가?
- 실제 금융 승인처럼 오해할 표현이 없는가?

## 에이전트에게 요청하는 예시

다음과 같이 결과보다 과정을 구체적으로 요청하면 디자인 일관성이 좋아집니다.

```text
코드부터 작성하지 마.
먼저 우리 서비스와 비슷한 실제 금융 사이트 5개를 찾아
레이아웃, 타이포그래피, 색상, 간격, 폼 구조를 비교해.

그대로 복제하지 말고 반복되는 디자인 원칙을 추출해
이 교육용 ML 서비스에 맞는 DESIGN.md를 작성해.

그 문서의 규칙을 벗어나지 않는 범위에서 전체 화면을 구현하고,
정상·오류·로딩 상태와 모바일·데스크톱 화면을 직접 검사해 수정해.
```
